# 🔑 Zodとは？
（型とバリデーションの統合）Zodは、JavaScriptやTypeScriptのデータを**「実行時
（Runtime）に検証する」**ためのスキーマ宣言ライブラリです。

## 1. 役割：データの「契約書」作成
Zodのコードは、そのデータがどのような形（型）でなければならないかという「契約書（スキーマ）」
を作成します。
【ユーザー登録データのスキーマ例】TypeScriptimport { z } from 'zod';

// ユーザー登録で必要なデータの「形」を定義
export const signupSchema = z.object({
  email: z.string().email(), // ⬅️ 1. 必ず文字列で、かつメールアドレスの形式であること
  password: z.string().min(8), // ⬅️ 2. 必ず文字列で、かつ最低8文字以上であること
});
## 2. Zodが解決する2つの問題（最大のメリット）Zodが優れているのは、この一つのスキーマ定義で、
従来の開発で必要だった2つの工程を同時に解決できる点です。
項目Zodが提供する機能なぜこれが優れているかバリデーションユーザーがAPIに送ってきたデータが、
上記スキーマの**ルール（8文字以上など）を満たしているか、実行時にチェックする。
Controller層（受付）のコードがシンプルになり、複雑な if/else によるチェックが不要になる。
型生成定義したスキーマから、自動的にTypeScriptの型**を生成する。
**「バリデーションの定義」と「TypeScriptの型定義」**を別々に書く必要がなくなり、二重の手間とミスを防げます。
## 3. Zodが使われる場所あなたが今行っているリファクタリングで、Zodは以下の場所で活用されます。
Controller層（受付）: リクエストボディ（req.body）を受け取った直後に、Zodを使ってバリデーションをかけます。
Service層（頭脳）: Controllerから渡されたデータは、Zodによって**「正しい形が保証されている」**
ため、Service層は安心してロジック（DBへの保存など）に集中できます。

## 3. enum
const FishEnumSchema = z.enum(["Salmon", "Tuna", "Trout"]);
type FishEnum = z.infer<typeof FishEnumSchema>;
// 'Salmon' | 'Tuna' | 'Trout'

const VALUES = ["Salmon", "Tuna", "Trout"] as const;
const FishEnumSchema = z.enum(VALUES);

FishEnumSchema.enum; // => { Salmon: "Salmon", Tuna: "Tuna", Trout: "Trout" }
FishEnumSchema.options; // ["Salmon", "Tuna", "Trout"];

## 4. object
// all properties are required by default
const Dog = z.object({
  name: z.string(),
  age: z.number(),
});

// extract the inferred type like this
type Dog = z.infer<typeof Dog>;

// equivalent to:
type Dog = {
  name: string;
  age: number;
};

# zodの非常に強力な点
z.infer<...>は、定義したスキーマから自動的にTypeScriptの型を生成（推論）する機能です。
typeof registerSchemaでスキーマの型を取得し、そこからz.inferが対応するデータ構造の型（例: { body: { email: string, ... } }）を導き出します。
['body']で、その中からbodyオブジェクトの型だけを抜き出しています。
このRegisterInput型を後のステップでコントローラーで使うことで、req.bodyの中身が完全に型付けされ、req.body.emaiのように安全にプロパティへアクセスできるようになります（typoなども防げます）。

```
// 型をエクスポート
export type RegisterInput = z.infer<typeof registerSchema>['body'];
export type LoginInput = z.infer<typeof loginSchema>['body'];
```

# try　〜　catch
✅ 結論：try〜catchは「信頼できない処理」のガード
あなたが現在取り組んでいるバックエンド実装では、以下の3つの領域で try〜catchが不可欠です。

1,外部通信: DB、外部API（fetch、Prisma）
2,入力データ: バリデーション、JSON解析
3,セキュリティ: JWTの検証やパスワード照合
