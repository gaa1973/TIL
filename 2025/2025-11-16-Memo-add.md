# 1. 全体像

このアプリケーションは、React で構築されたフロントエンドと、Express (Node.js) で構築されたバックエンド API の 2 つの主要な部分から構成されています。

フロントエンド: ユーザーが操作するインターフェース（UI）を提供します。http://localhost:5173 などで動作します。
バックエンド: データ処理、データベースとの連携、ユーザー認証などのビジネスロジックを担当します。http://localhost:8000 で動作します。

# 2. フロントエンドの処理 (App.tsx)

フロントエンドは、現在すべての機能が App.tsx という単一のコンポーネントファイルに実装されています。

## 2.1. 状態管理 (State)

コンポーネントは useState フックを使い、以下の状態を管理しています。

email, password: ログイン/新規登録フォームの入力値。
message: ユーザーへの通知メッセージ（例：「ログイン成功」「エラーが発生しました」）。
isLoggedIn: ユーザーがログインしているかどうかの状態 (true/false)。
isLoading: アプリケーション起動時に、ログイン状態を確認中であることを示す状態。
memos: バックエンドから取得したメモの一覧。
newMemoTitle, newMemoContent: 新規メモ作成フォームの入力値。

## 2.2. 画面表示のロジック

アプリケーションは、isLoading と isLoggedIn の状態に応じて表示する内容を切り替えます。

ローディング画面: isLoading が true の間、「認証状態を確認中...」と表示されます。
ログイン画面: isLoading が false かつ isLoggedIn が false の場合、ログイン/新規登録フォームが表示されます。
メモ帳画面: isLoading が false かつ isLoggedIn が true の場合、メモ作成フォームとメモ一覧が表示されます。

## 2.3. 主要な処理の流れ

アプリケーション起動時 (リロード時)

useEffect フックが一度だけ実行されます。
バックエンドの /api/auth/me エンドポイントにリクエストを送信し、有効なセッション（ログイン状態）が残っているか確認します。
セッションが有効な場合: isLoggedIn を true に設定し、/api/memos からメモ一覧を取得します。
セッションが無効な場合: isLoggedIn は false のままになります。
確認処理が完了すると、isLoading が false になり、状態に応じた画面が表示されます。
新規登録 (handleRegister)

ユーザーが入力した email と password を /api/auth/registration に POST リクエストで送信します。
成功すると、isLoggedIn が true になり、メモ帳画面に切り替わります。
ログイン (handleLogin)

入力された email と password を /api/auth/login に POST リクエストで送信します。
成功すると、バックエンドからセッション情報を含む Cookie が発行され、フロントエンドの isLoggedIn が true になり、メモ帳画面に切り替わります。
メモ作成 (handleCreateMemo)

入力されたタイトルと内容を /api/memos に POST リクエストで送信します。
成功すると、入力フォームをクリアし、再度 /api/memos から最新のメモ一覧を取得して画面を更新します。

# 3. バックエンドの処理 (API)

フロントエンドのコードから、バックエンドには以下の API エンドポイントが実装されていることが推測されます。

## 3.1. 認証関連 (/api/auth)

POST /api/auth/registration

役割: 新規ユーザー登録。
処理: リクエストボディから email と password を受け取り、パスワードをハッシュ化した上でデータベースに新しいユーザーを作成します。
POST /api/auth/login

役割: ユーザーログイン。
処理: email と password を受け取ります。データベース内のユーザー情報と照合し、認証が成功すればセッションを作成し、セッション ID を含む Cookie をレスポンスに含めて返します。
GET /api/auth/me

役割: 現在のログイン状態の確認。
処理: リクエストに含まれる Cookie からセッション ID を検証します。セッションが有効であれば、ユーザー情報を返すか、成功ステータス（HTTP 200）を返します。無効であれば、認証エラー（HTTP 401）を返します。
3.2. メモ関連 (/api/memos)
GET /api/memos

役割: ログイン中ユーザーのメモ一覧取得。
処理: 現在のセッション情報からユーザーを特定し、そのユーザーに紐づくすべてのメモをデータベースから取得して返します。
POST /api/memos

役割: 新しいメモの作成。
処理: セッションからユーザーを特定し、リクエストボディの title と content を使って、そのユーザーの新しいメモをデータベースに保存します。
