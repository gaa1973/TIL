## updateやdeleteではなく updateMany や deleteMany を使う理由は、Prisma の仕様上の制約とセキュリティのためです。

1. Prisma のupdate / delete の制約Prisma のupdate や
delete
 メソッドは、where 句に 「一意（ユニーク）な条件」しか指定できない というルールがあります。 通常、
id
 だけがユニークなので、以下のようにしか書けません。

typescript
// OK: idはユニークなので通る
prisma.memo.update({ where: { id: 1 }, ... });

// NG: authorIdはユニークではないので、updateでは使えない！
prisma.memo.update({ where: { id: 1, authorId: 5 }, ... });
これだと、「IDが1なら、誰のデータでも更新できてしまう」ため、事前に findUnique などで所有者チェックをする必要が出てきます（＝2回DBアクセスが必要）。

2. updateMany / deleteMany の特徴
一方で、...Many 系は 「条件に一致するものをすべて処理する」 というメソッドなので、ユニーク制約に関係なく、好きな条件を組み合わせられます。

typescript
// OK: idが1 かつ authorIdが5 のものだけを更新
prisma.memo.updateMany({ where: { id: 1, authorId: 5 }, ... });
これを利用すると：

IDが一致しても、所有者（authorId）が違えば条件にヒットしない ので、更新されません（件数0になる）。
IDも所有者も一致すれば、1件だけヒットする ので、意図通り更新されます。
つまり、「所有者チェック」と「更新処理」を1回のデータベース操作で安全に行うためのテクニックとして updateMany を使っています。
